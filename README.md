# 社区独居老人一键求助 · 上门核实转介回访平台

面向社区独居老人照护场景：老人通过**智能按钮、电话、社区小程序**发起求助后，值班社工在同一条事件中完成
**求助受理 → 研判分类 → 分级转介 → 上门核实 → 后续服务 → 家属沟通 → 回访归档**，
并在归档时联动更新老人照护画像、家属响应表现、邻里协助可信度与下一次主动关怀计划，
支撑社区管理者按风险等级、响应时长、服务类型、回访结果复盘独居老人照护能力。

针对**无法开门**场景，平台内置多方确认处置流程：社工到达后老人无响应但屋内有灯光时，
引导值班人员**依次联系家属 → 物业 → 邻居 → 派出所**并逐步留痕；确需破门或请锁匠时，
强制登记**授权依据与现场见证人**，并跟踪锁具更换、门窗修复、费用垫付与老人后续安置，
家属到场后可查看完整处置轨迹并确认费用承担（家庭承担 / 社区救助 / 保险理赔），避免救助后的责任争议。

## 技术栈

- 前端：Vue 3 + Vite + Element Plus + Pinia + Vue Router + ECharts（SSE 实时告警）
- 后端：Spring Boot 3.3 + Spring Data JPA + Redis（登录令牌）+ PostgreSQL
- 基础设施：Docker Compose 一键启动 postgres / redis / backend / frontend

## 一、Docker 一键启动（推荐）

前置：安装 Docker 与 Docker Compose。

```bash
cd 170-feature-1-a
docker compose up -d --build
```

启动后访问：

| 服务 | 地址 |
| --- | --- |
| 前端页面 | http://localhost:8081 |
| 后端 API | http://localhost:8080/api |

首次启动自动建表并写入 5 个测试账号和 3 位示例老人档案（周桂兰、吴德海、郑秀珍）。

停止与清理：

```bash
docker compose down          # 停止（保留数据卷）
docker compose down -v       # 停止并清空数据库/上传文件
```

## 业务功能与验证路径

### 1. 一条事件贯通全流程（“求助—核实—上门—转介—服务—家属沟通—回访”）

值班工作台 →「模拟一键求助」选择老人与来源（智能按钮/电话/小程序），填写语音内容与定位 →
进入事件详情，依次操作：

1. **值班研判**：生活协助 / 身体不适 / 跌倒风险 / 情绪危机 / 误触，严重程度 低/中/高/紧急；
2. **转介通知**：按严重程度通知网格员 / 邻里志愿者 / 家庭医生 / 120，可登记邻居代报及信息是否清晰，并更新受理/到场状态；
3. **上门核实**：入户方式（钥匙、门禁密码、智能锁授权、邻居/家属开门、破锁、未能入户）、现场照片上传、
   老人状态、是否联系家属、是否需要送医、是否拒绝就医、是否需要临时照护、后续服务建议、家中安全隐患；
4. **家属沟通**：多次拨打接通情况与态度（连续未接通自动判定“家属长期不接电话”）；
5. **后续服务**：临时照护、送医陪诊、日常巡访、助餐、适老化改造、心理陪伴；
6. **回访归档**：好转/平稳/恶化/未联系上 + 满意度 + 下一次主动关怀计划，归档联动更新画像。

右侧固定展示**老人照护画像**（长期独居、燃气报警器、最近家属探访、医生随访结论、历史误触、
基础病、门禁信息、紧急联系人、邻里响应人），底部为全过程时间线留痕。

### 2. 七类特殊风险自动/手动标记，全程沉淀在同一事件

| 风险 | 触发方式 |
| --- | --- |
| 无法开门 | 上门记录“未能入户”或入户方式为未能入户 |
| 定位偏移 | 求助坐标与档案住址距离 > 500 米自动判定（阈值可配） |
| 家属长期不接电话 | 档案联系人已标记，或同一事件累计 ≥2 次未接通 / 联系人累计未接通率超 2/3 |
| 邻居代报信息不清 | 转介时勾选“邻居代报·信息不清”，同时下调该邻里可信度 |
| 老人拒绝就医 | 上门记录勾选 |
| 家中存在安全隐患 | 上门填写隐患描述（自动建议适老化改造） |
| 频繁夜间求助 | 22:00–06:00 求助，近 30 天夜间求助 ≥3 次自动标记（阈值可配） |

### 3. 无法开门 · 多方确认处置（防责任争议）

上门记录“未能入户”后，事件详情页出现**多方确认处置**面板（也可由“补充风险标记”触发）：

1. **启动确认**：记录老人无响应、屋内有灯光等现场情况，关联未能入户的上门记录；
2. **依次联系**：平台按 **家属 → 物业 → 邻居 → 派出所** 四步引导（步骤条实时提示下一联系对象），
   每一步登记联系人、电话、联系方式、是否联系上、对方反馈、是否到场协助；
   服务端强制顺序（跳步登记返回提示），同一对象可多次联系；
3. **两条结案路径**：
   - *无需破门*：家属/物业/邻居到场开门，登记结案说明；
   - *破门/请锁匠*：四方联系全部留痕后才允许登记，**授权依据**（家属电话/现场授权、民警现场授权、
     社区应急预案授权）、**授权人、执行人、现场见证人**为必填，并可登记物业/民警见证人与损坏情况；
4. **后续修复与安置**：补录锁具更换、门窗修复、物业见证、老人后续安置（家中留观/送医/家属接回/社区临时照护点）；
5. **费用明细**：逐笔登记开锁费、锁具更换、门窗修复等费用，记录**垫付方**（社区/家属/物业）
   与**承担方**（家庭承担/社区救助/保险理赔/待确认）；
6. **家属到场确认**：家属查看完整处置轨迹（联系记录、授权见证、费用明细、时间线）后，
   登记对费用分担方案的确认意见（认可/部分认可/有异议），全程留痕可查。

### 4. 事件不停在处置结果——归档联动更新

回访归档后系统自动：

- 重算老人**综合风险等级**；
- 更新**家属响应表现评分**（本事件接通率）与联系人接通统计；
- 更新**邻里协助可信度**（有效响应、代报信息质量）；
- 累加**误触记录**；
- 依据跌倒/隐患/情绪危机/临时照护等勾选**增加日常巡访、助餐、适老化改造、心理陪伴**建议；
- 生成**下一次主动关怀计划**（可手动指定，否则按严重程度 1/3/7/14 天自动排期）。

### 5. 社区管理者复盘

「照护能力复盘」页（admin 账号可看全部数据）支持按时间区间统计：
事件总数/夜间/送医、按风险等级分布、按研判类型分布、按服务类型分布、按回访结果分布、
每日求助趋势、平均/最快/最慢响应时长与 15 分钟到场率、七类风险场景出现频次。

## 已执行的验证（本地实际验证结论）

### 2026-10-06（本轮：无法开门多方确认）

验证环境：JDK 17 + Maven 3.8 + Node 22 + PostgreSQL 15（本地 5433 实例）+ Redis 7。

1. **后端编译打包**：`mvn package -DskipTests` 成功，产出 `target/eldercare.jar`。
2. **多方确认全链路 API 冒烟**（curl，worker 账号，17 项断言全部通过）：
   - 周桂兰智能按钮求助 → 研判（跌倒风险/紧急）→ 上门“未能入户”自动标记 `CANNOT_OPEN_DOOR`；
   - 启动多方确认（老人无响应+屋内有灯光）；**重复启动被拒绝**；
   - **顺序校验**：未联系家属直接联系派出所被拦截并提示“请先联系家属”；
   - 依次登记 家属（2 次：儿子未接通、女儿接通授权）→ 物业 → 邻居 → 派出所，全部留痕；
   - **时序校验**：另一事件四方未联系齐时登记破门被拦截；
   - 登记破门处置（家属电话授权+授权人+锁匠+2 名见证人+物业/民警见证+损坏情况），处置单自动结案为“破门救助”；**缺见证人被 400 校验拦截**；
   - 补录锁具更换（C 级锁芯）、门窗修复、物业见证、老人送医安置；
   - 登记 3 笔费用（开锁费/锁具/门框修复，社区垫付），开锁费承担方由“待确认”改为“保险理赔”，合计 ¥830；
   - 女儿到场确认“认可费用分担”；**结案后再登记联系被拦截**；
   - 事件详情聚合返回 5 步联系、破门记录、3 笔费用、1 条家属确认，时间线含 13 条 DOOR 留痕；
   - 事件 2 验证“家属到场开门”结案路径；事件 1 回访归档后处置轨迹仍可完整查看。
3. **鉴权**：无令牌访问 `/api/events/1/door-escalation` 等新端点返回 `code:401`。
4. **前端**：`npm run build` 构建成功；Vite dev（5173）启动后代理 `/api` 正常，事件详情可获取多方确认聚合数据。
